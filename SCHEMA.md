# TripStory Data Schemas

These schemas keep the pipeline staged: media intelligence builds grounded scene memory, the story planner selects beats, the narration writer produces lines, and the renderer maps those lines to source windows.

## 1. Scene Memory

Persisted as `scene_memory.json` and exposed on the session as `scene_memories`.

```json
{
  "scene_id": "clip1_scene_001",
  "project_id": "session-id",
  "clip_id": "clip1",
  "clip_filename": "market.mp4",
  "source_window_id": "win_001",
  "time_range": {
    "start_sec": 2.0,
    "end_sec": 7.0
  },
  "transcript": "we finally made it to the market",
  "visual_summary": "walking into a crowded outdoor market",
  "entities": ["speaker", "friend", "market stalls"],
  "actions": ["walking", "looking around"],
  "location": "outdoor market",
  "tone": "excited",
  "audio_value": "high",
  "visual_value": "high",
  "ambient_audio_value": "medium",
  "narrative_role_candidates": ["hook", "setup", "progression"],
  "story_energy": 0.82,
  "grounding_confidence": 0.87,
  "evidence": [
    {"type": "transcript", "value": "we finally made it to the market"},
    {"type": "visual", "value": "multiple vendor stalls visible"}
  ],
  "risks": ["speaker identity not fully certain"]
}
```
