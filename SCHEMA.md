# TripStory Data Schemas

This document defines the core JSON structures that enable the TripStory pipeline to separate heavy computer vision tasks from the lightweight text-based Story Planner.

## 1. Scene Memory (Clip Manifest)
This schema represents the "Grounded Scene Memory". It is generated during Milestone 1 by the intelligence layer (analyzing audio, cuts, blurriness, and VLM frame summaries). This is the *only* data the Story Planner sees.

```json
{
  "clip_id": "string (uuid)",
  "filename": "string",
  "duration_seconds": "float",
  "resolution": {
    "width": "integer",
    "height": "integer"
  },
  "overall_quality_score": "float (0.0 to 1.0)",
  "audio_profile": {
    "has_speech": "boolean",
    "speech_transcript": "string (optional)",
    "volume_db": "float"
  },
  "smart_windows": [
    {
      "window_id": "string",
      "start_time": "float",
      "duration": "float",
      "visual_evidence": "string (VLM generated summary of this specific scene)",
      "score": "float (0.0 to 1.0 based on blur/quality/motion)",
      "flags": ["dark", "shaky", "face_detected"]
    }
  ]
}
```

## 2. Story Plan (Planner Output)
This schema is generated by the Story Planner LLM (Milestone 2 & 3). It takes the user's context and the `Scene Memory` above, and outputs concrete editing decisions and voiceover.

```json
{
  "title": "string",
  "language": "string",
  "tone": "string",
  "narrative_arc": "string (brief summary of the planned story)",
  "target_duration_seconds": "float",
  "voiceover_script": "string (the complete joined script)",
  "edit_decisions": [
    {
      "segment_id": "integer (order in timeline)",
      "clip_id": "string (must match a clip_id from the manifest)",
      "window_id": "string (must match a window_id from the manifest)",
      "start_time": "float (when to start cutting the source clip)",
      "duration": "float (how long the cut should be)",
      "role": "string (e.g., 'hook', 'b-roll', 'climax', 'outro')",
      "reason": "string (why the LLM chose this clip based on visual_evidence)",
      "audio_strategy": "string (e.g., 'mute_source', 'mix_under_voice', 'keep_source')"
    }
  ],
  "voiceover_segments": [
    {
      "segment_id": "integer (must strictly match the edit_decisions segment_id)",
      "clip_id": "string",
      "start_time": "float (when the voiceover starts relative to the segment)",
      "duration": "float (estimated duration of this spoken line)",
      "voiceover": "string (the actual text to be spoken by TTS)",
      "purpose": "string (e.g., 'context setting', 'reaction')"
    }
  ]
}
```

## 3. User Trip Context
Provided by the user via the mobile/web UI before generation starts.

```json
{
  "destination": "string",
  "travel_dates": "string",
  "who_was_there": "string",
  "vibe": "string",
  "special_instructions": "string (optional user overrides)"
}
```
